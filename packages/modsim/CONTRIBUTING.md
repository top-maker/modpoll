# Contributing to modsim

Simulator code, runtime and scenario language changes target the affected tool
line (`v2` for model-driven development). Run relevant checks from the root:

```sh
uv sync --all-groups
make check
make test
uv run python tools/generate-td.py --check
uv run --group docs mkdocs build -s
```

Device TMs, metadata, sources and product-specific scenarios belong in
[Open Modbus Catalog](https://github.com/top-maker/open-modbus-catalog), targeting
its `main` through a PR and required catalog CI. Do not add editable device copies
here. A new model submission needs an executable TM and source/permission/known
limits; maintainers can help complete metadata.
Never include private endpoints, credentials or customer data in public inputs.

The model-source lock and downloader are consumers of immutable public data.
For a data update, pin the full catalog commit, review every file and hash, update examples/model-source.yaml through a PR, run the downloader, then
run affected simulator/client tests. The tests/fixtures tree is a frozen runtime
regression fixture, not a contribution catalog. Generated TD fixtures are
regenerated by tools/generate-td.py, never hand edited.

CI covers Python 3.10 and 3.14. Local loopback checks do not certify hardware,
physical outputs or engineering-unit accuracy. See docs/release-process.md for
independent tool publishing; a data update does not require an app release.
