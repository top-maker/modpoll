Basic Usage

Modpoll v2.0.0a11 - A New Command-line Tool for Modbus and MQTT

usage: modpoll [-h] [-v] [-f CONFIG [CONFIG ...]] [--report [FILE]]
               [--upload [FILE]] [--yes] [--confirm POINT [POINT ...]]
               [--reject POINT [POINT ...]] [--param NAME=JSON]
               [--unit-id UNIT_ID] [-d] [-r RATE] [-1] [--interval INTERVAL]
               [--tcp TCP] [--tcp-port TCP_PORT] [--udp UDP]
               [--udp-port UDP_PORT] [--serial SERIAL]
               [--serial-baud SERIAL_BAUD] [--serial-parity {none,odd,even}]
               [--timeout TIMEOUT] [-o EXPORT] [--precision auto|N]
               [--mqtt-version {3.1.1,5.0}] [--mqtt-host MQTT_HOST]
               [--mqtt-port MQTT_PORT] [--mqtt-clientid MQTT_CLIENTID]
               [--mqtt-publish-topic-pattern MQTT_PUBLISH_TOPIC_PATTERN]
               [--mqtt-subscribe-topic-pattern MQTT_SUBSCRIBE_TOPIC_PATTERN]
               [--mqtt-diagnostics-topic-pattern MQTT_DIAGNOSTICS_TOPIC_PATTERN]
               [--mqtt-qos {0,1,2}] [--mqtt-user MQTT_USER]
               [--mqtt-pass MQTT_PASS] [--mqtt-use-tls] [--mqtt-insecure]
               [--mqtt-cacerts MQTT_CACERTS]
               [--mqtt-tls-version {tlsv1.2,tlsv1.1,tlsv1}] [--mqtt-single]
               [--diagnostics-rate DIAGNOSTICS_RATE] [--autoremove]
               [--loglevel {DEBUG,INFO,WARNING,ERROR,CRITICAL}] [--timestamp]
               [--delay DELAY] [--framer {default,ascii,rtu,socket}]

Named Arguments

-v, --version

show program’s version number and exit

-f, --config

Local path or URL of a v1 CSV or WoT TM/TD JSON configuration, or modiohub:<id>@<version> for a custom Thing Model in your ModioHub Workspace (run modpoll login first unless it is shared). The format is detected from the content, not the filename. Required unless –device is given.

--param

Typed TM placeholder binding (requires the profile 0.2 interpreter)

Default: []

--unit-id

Override instance Unit ID (1-254); otherwise use the TD, the legacy CSV default, or 1

-d, --daemon

Run in daemon mode without printing result. Recommended to use with docker

Default: False

-r, --rate

The sampling rate (s) to poll modbus device, Defaults to 10.0

Default: 10.0

-1, --once

Only run polling at one time

Default: False

--interval

The time interval in seconds between two polling, Defaults to 0.5

Default: 0.5

--tcp

Explicit TCP host; a profile 0.2 TD uses its endpoint when omitted

--tcp-port

Port for MODBUS TCP. Defaults to 502

--udp

Act as a Modbus UDP master, connecting to host UDP

--udp-port

Port for MODBUS UDP. Defaults to 502

Default: 502

--serial, --rtu

pyserial URL (or port name) for serial transport (alias: –rtu)

--serial-baud, --rtu-baud

Baud rate for serial port. Defaults to 9600

Default: 9600

--serial-parity, --rtu-parity

Possible choices: none, odd, even

Parity for serial port. Defaults to none

Default: “none”

--timeout

Response time-out seconds for MODBUS devices, Defaults to 3.0

Default: 3.0

-o, --export

The file name to export point values

--precision

Decimals to show for float values. The default ‘auto’ keeps the precision of the source data; N rounds every float to at most that many decimals.

--mqtt-version

Possible choices: 3.1.1, 5.0

MQTT version. Defaults to MQTT v3.1.1

Default: “3.1.1”

--mqtt-host

MQTT server address. Skip MQTT setup if not specified

--mqtt-port

1883 for non-TLS or 8883 for TLS, Defaults to 1883

Default: 1883

--mqtt-clientid

MQTT client name, If qos > 0, set unique name for multiple clients

--mqtt-publish-topic-pattern

Topic pattern for MQTT publish. Use {{device_name}} as placeholder for the device names in Modbus config. Defaults to “modpoll/{{device_name}}/data”

Default: “modpoll/{{device_name}}/data”

--mqtt-subscribe-topic-pattern

Topic pattern for MQTT subscribe. Defaults to “modpoll/+/set”

Default: “modpoll/+/set”

--mqtt-diagnostics-topic-pattern

Topic pattern for MQTT diagnostics. Use {{device_name}} as placeholder for the device names in Modbus config. Defaults to modpoll/{{device_name}}/diagnostics

Default: “modpoll/{{device_name}}/diagnostics”

--mqtt-qos

Possible choices: 0, 1, 2

MQTT QoS value. Defaults to 0

Default: 0

--mqtt-user

Username for authentication (optional)

--mqtt-pass

Password for authentication (optional)

--mqtt-use-tls

Use TLS

Default: False

--mqtt-insecure

Use TLS without providing certificates

Default: False

--mqtt-cacerts

Path to ca keychain

--mqtt-tls-version

Possible choices: tlsv1.2, tlsv1.1, tlsv1

TLS protocol version, can be one of tlsv1.2 tlsv1.1 or tlsv1

Default: “tlsv1.2”

--mqtt-single

Publish each value in a single topic. If not specified, groups all values in one topic.

Default: False

--diagnostics-rate

Time in seconds as publishing period for each device diagnostics

Default: 0

--autoremove

Automatically remove poller if modbus communication has failed 3 times.

Default: False

--loglevel

Possible choices: DEBUG, INFO, WARNING, ERROR, CRITICAL

Set log level, Defaults to INFO

Default: “INFO”

--timestamp

Add timestamp to the result

Default: False

--delay

Time to delay sending first request in seconds after connecting. Default to 0

Default: 0

--framer

Possible choices: default, ascii, rtu, socket

The type of framer for Modbus messages. Serial supports ascii/rtu; TCP/UDP use socket.

Default: “default”

verification

–report reads every point of one Thing Model once, read-only and without retries, and reports which points could be read; –upload sends a verification report to ModioHub

--report

Read every point of the model once and write the verification report to FILE (‘-’ prints it). Without FILE the save location, your judgment of the values and whether to upload are asked interactively. The report lists each point’s result and carries no address, Unit ID, serial number or value.

--upload

Upload a verification report to ModioHub. With FILE (or a file chosen interactively, the newest report-*.json by default) a saved report is uploaded without reading a device: it is shown for confirmation and uploaded once you agree; you are signed in with the browser only when no login exists. Together with –report, the report of the verification read is uploaded instead of only being saved.

--yes

Answer the report questions without asking: keep the default report file and upload it. Needs –report or –upload and an existing sign-in (the browser sign-in is interactive).

Default: False

--confirm

Points whose values you checked and found right (‘all’ for every point), for the report

Default: []

--reject

Points whose values you checked and found wrong, for the report

Default: []

The config option is required.

Commandline Usage

  • Connect to Modbus TCP device

    modpoll --tcp 192.168.1.10 --config examples/modsim.tm.json

  • Connect to Modbus serial device

    modpoll --serial /dev/ttyUSB0 --serial-baud 9600 --config examples/modsim.tm.json

  • Connect to Modbus TCP device and publish data to remote MQTT broker

    modpoll --tcp 192.168.1.10 --config examples/modsim.tm.json --mqtt-host broker.emqx.io

  • Connect to Modbus TCP device and export a local JSON snapshot

    modpoll --tcp 127.0.0.1 --tcp-port 5020 --config examples/modsim.tm.json --export data.json

  • Replay an exported snapshot with modsim on this computer. A snapshot is simulation data as it stands; points that were not read keep their defaults. It holds readings of a real device, so keep it local.

    modpoll --once --tcp 192.168.1.10 --config examples/modsim.tm.json --export snapshot.json
modsim --config examples/modsim.tm.json --port 5020 --data snapshot.json

Value rendering

The terminal table, the MQTT payload and the JSON snapshot show one number for one reading. The default --precision auto keeps the precision the source data carries:

  • A register value with a modpoll:multiplier is shown as its exact decimal, so 2301 scaled by 0.1 reads 230.1 rather than 230.10000000000002.

  • A float16 or float32 register is shown as the shortest decimal that reads back as the same value at that width, so 12.34 stays 12.34.

  • A float64 register keeps its full value.

  • Integers, booleans and strings are shown unchanged.

An explicit --precision N rounds every float to at most N decimals:

modpoll --tcp 192.168.1.10 --config examples/modsim.tm.json --precision 2

Rounding a scaled reading can change the raw register value it names. The exported snapshot doubles as modsim simulation data, so Modpoll logs a warning when that happens. The value is still written as asked for.

Configuration File

The configuration file (–config) defines the devices, pollers, and points to be read. It can be a WoT TM/TD JSON file or a v1 CSV file; the format is detected from the content, no other configuration flag is needed.

For register references (i.e., Holding or Input registers) with a dtype of bool, you can specify a single bit to be extracted from the 16-bit register. This is done by appending :bit to the address, where bit is an integer from 0 to 15.

  • 40110: Reads the entire 16-bit register at address 40110.

  • 40110:15: Reads the 16-bit register at address 40110, extracts bit 15, and returns a boolean value.

The bit is extracted from the final 16-bit value after byte/word swapping based on the poller’s endianness configuration.

Framers and transports

  • Serial (–serial, alias –rtu) supports framers rtu and ascii (e.g., –serial … –framer ascii). Binary framer was removed in pymodbus 3.9+. If –framer default is used, pymodbus defaults to RTU framer.

  • TCP/UDP (–tcp/–udp) use the socket framer; other framers are rejected. If –framer default is used, pymodbus defaults to socket framer.

MQTT write commands with malformed payloads, invalid values, ambiguous device names, or a retained-message flag are ignored and logged. Register arrays use FC16 and support 1–123 unsigned 16-bit values. Configure the broker not to retain messages on write-command topics; the MQTT retained flag is not guaranteed to remain set during live forwarding.

Points that fail in a poll cycle are omitted from MQTT output and represented as null in JSON snapshots. Multiple configuration files are combined into one atomically replaced snapshot.
